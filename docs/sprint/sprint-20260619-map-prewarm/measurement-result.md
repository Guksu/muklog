# map-prewarm 측정 결과 (T-MEASURE)

> PERF-TEMP 임시 계측 + `scripts/mapPerf.mjs` 분석기로 측정 후, 종료 단계에서 계측·분석기는 제거됨.
> 본 문서는 감사 추적용으로 측정값을 보존한다(재현하려면 PERF-TEMP를 다시 심어야 함).
> 환경: **dev / iOS 시뮬레이터**(Dev Client + Metro). release/실기기는 WKWebView 콜드 부팅이 더 빠를 가능성이 큼.

## 병목 진단 (프리워밍 전)

지도탭 콜드 진입은 전체 ~3.76초이며, **88%가 WebView 부팅(WKWebView 인스턴스 생성 + 첫 HTML 스크립트 실행)** 이었다.
Kakao SDK 다운로드·핀 RPC는 병목이 아니었다(→ SDK 캐싱·핀 프리페치는 첫 페인트 체감 기여 0).

| 구간 | 시간 |
|------|------|
| WebView 부팅(마운트→스크립트) | **2642ms** ← 병목 |
| SDK 다운로드 | 249ms |
| kakao.maps.load | 28ms |
| 지도 생성(INIT→첫 페인트) | 36ms |
| 마커 렌더 | 76ms |
| 핀 RPC 왕복 | 721ms (지도보다 ~3초 먼저 끝남, INIT에 동봉) |
| **전체(마운트→마커 렌더)** | **3760ms** |

## 개선 후 (전략 A′ — 루트 숨김 WebView 프리워밍)

홈 체류 중 프리워머가 숨김 WebView로 WKWebView 프로세스 풀 + Kakao SDK HTTP 캐시를 데움.
지도탭 진입(프리워밍 ~53초 후) 측정:

| 구간 | 전 | 후 | 개선 |
|------|-----|-----|------|
| WebView 부팅(마운트→스크립트) | 2642ms | **1219ms** | **−1423ms (−54%)** |
| SDK 다운로드 | 249ms | **3ms** | −246ms (−99%, 캐시 적중) |
| kakao.maps.load | 28ms | 10ms | — |
| 지도 생성(INIT→첫 페인트) | 36ms | 43ms | — |
| 핀 RPC 왕복 | 721ms | 136ms | (warm) |
| **전체(마운트→마커 렌더)** | **3760ms** | **1407ms** | **−2353ms (−63%)** |

격리 검증: 프리워머 그룹(`[mapPerf:prewarm]`)엔 `rn:rpc-*`·권한 이벤트 없음 → blank 부팅(권한 팝업·RPC 앞당김 없음) 확인. RPC는 지도탭 진입 시 1회만.

## 남은 한계 / 후속 후보 (이번 스프린트 OUT)

- 잔여 1219ms는 **새 WKWebView 인스턴스 생성** 자체 비용 — 워밍으로 제거 불가. 더 줄이려면 전략 B(프리워밍한 인스턴스를 지도탭이 reparent해 재사용)가 필요하나 RN에서 깨지기 쉬워 plan에서 제외.
- **release/실기기 재측정** 권장 — dev/시뮬 수치는 과대평가 가능.
- SDK 캐싱·핀 프리페치는 데이터상 첫 페인트 체감 기여가 작아 별도 추진 가치 낮음(참고용).
