# Sprint: 맛집 작성/편집 정합 (sprint-20260620-editor-fidelity)

## 단일 기능
맛집 작성/편집 화면(`MuklogEditor`)을 디자인 킷 `mk-log.jsx`(MuklogEditor 385-474)에 정합. **사용자 결정으로 저장조건·카테고리는 현행 유지**, 나머지 킷 정합만.

## 사용자 결정 (이번 스프린트 적용)
- **저장 조건 = 현행 유지**(메모 5자 필수, 별점 선택). 킷의 "장소+별점 필수/메모 선택"으로 바꾸지 **않는다**. → `canSave` 로직 불변.
- **카테고리 = 현행 유지**(8종 칩 수동 선택 필드 유지). 킷의 자동결정으로 제거하지 **않는다**. → 카테고리 필드 불변.

## 작업 범위 (킷 정합 — 3건)
1. **저장 성공 토스트**(킷 mk-log:400): 저장 성공 시 토스트 — 신규 "맛집을 기록했어요! 🍽️" / 편집 "기록을 수정했어요"(positive). 토스트 인프라(`src/components/Toast.tsx`·`useToast.ts`) 존재 → 저장 플로우(`MuklogEditor` → `onSaved` → `MuklogEditorRoute.handleSaved`/goBack)에 배선. 현재 토스트 없음.
2. **별점 보조 텍스트**(킷 mk-log:449): 별점 옆 `rating ? rating.toFixed(1) : "어땠어요?"`(미선택 시 placeholder, fgAssistive). 현재 Stars만 렌더. **순수 표시**(현 저장로직과 무관 — rating 0 허용 그대로, 텍스트만 추가).
3. **검색 버튼 카피**(킷 mk-log:418): 장소 미선택 검색 버튼 "맛집 이름을 검색해요"(현재 "장소 검색 (카카오)").

## 제외 (사유 명시)
- **영상 안내 "🎬 2초 영상…"(킷 441)**: RN에 영상 업로드 기능 **미존재**(grep 확인 — 사진만). 없는 기능을 안내하면 거짓 약속 → **제외**. 영상 기능이 생기면 그때 카피 추가.
- 저장조건·카테고리: 위 사용자 결정대로 현행 유지.

## 인수조건 (= 테스트, TDD)
- **AC1** 저장 성공(신규) 시 "맛집을 기록했어요! 🍽️", 편집 시 "기록을 수정했어요" 토스트 노출(RN Testing Library + useToast). 저장 실패 시 토스트 없음(기존 에러 처리 유지).

## 리스크/엣지
- 토스트 배선 위치: 저장은 비동기(업로드 포함) → **성공 콜백에서만** 토스트(실패 시 기존 Alert/에러 유지). 신규/편집 분기는 `initial`(편집 모드) 유무로 판정.
