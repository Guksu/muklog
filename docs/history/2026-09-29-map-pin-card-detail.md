# 지도 우리 맛집 카드에서 먹로그 상세로 이동

## 1. 개요

UX 백로그 U11을 처리했다(위반 원칙 1·2). 지도 탭에서 우리 맛집 핀을 누르면 하단 카드가 뜨지만, 카드는 표시 전용이라 그 기록의 사진·메모를 보려면 먹로그 탭으로 돌아가 로그를 찾아 들어가야 했다. 지도에서 발견한 기록에서 바로 상세로 가는 경로가 없었다. 이번 변경으로 카드 전체가 먹로그 상세로 가는 버튼이 된다. 한 컴포넌트와 한 화면 배선이라 분할하지 않았다. 위시 카드의 액션(U12)은 별도 기능이라 제외했다.

## 2. 작업 내용

기획 → 퍼블리싱 → 구현 → 독립 검증 3종(qa-logic·qa-visual·qa-ux) → 수정 1회 → 재검증 순서로 진행했다. 전 과정은 워크플로 1회로 실행했다.

- `src/features/map/components/SelectedSpotCard/SelectedSpotCard.tsx` — 카드를 누를 수 있게 했다.
  - 선택 prop `onPress`를 더했다. 주면 카드 전체(패딩 포함)가 버튼 하나가 되고, 없으면 이전과 같은 비탭 카드다.
  - 하트 뒤에 `chevron-right`(18, `fgAssistive`)를 더했다. 킷에서 "눌러서 이동하는 카드"에 쓰는 표시다(LogCard `mk-home.jsx:55`, SheetAction `:211`). 킷의 선택 카드에는 없는 요소 하나를 더한 것이라 §4에 적었다.
  - 눌림 피드백은 공용 `MotionPressable`(lg / 0.7, 공용 Card·MuklogCard와 같은 등급)이다. 바깥 View가 배경·상단 radius·그림자를 맡고 안쪽 내용만 줄고 흐려진다. 화면 폭에 붙은 카드라 표면째 줄이면 양옆에 지도가 비치기 때문이다.
  - 접근성: 역할 버튼, 이름 "{가게명} 기록 보기", 힌트 "방문 기록을 자세히 볼 수 있어요". 보이는 글자 "기록 보기"는 넣지 않았다.
  - 하트는 장식 그대로다(토글 없음). 킷 줄 번호 주석을 현재 킷 기준(`:374-389`)으로 고쳤다.
- `src/navigation/screens/MapTabScreen/MapTabScreen.tsx` — 카드에 `onPress={() => navigation.navigate(Routes.MuklogDetail, { muklogId })}`를 배선했다.
  - `useNavigation<NavigationProp<AppStackParamList>>()`를 쓴다. 이 화면은 HomeTabs 안의 탭이라, 탭 라우터가 처리하지 못한 `navigate`가 부모 AppStack으로 올라간다(LogListScreen → LogScreen과 같은 선례).
  - `push`가 아니라 `navigate`다. 맨 위가 이미 같은 상세면 새로 쌓지 않아 연타해도 상세는 한 장이다. 화면 잠금은 두지 않았다(복귀 때 풀어야 하고, 안 풀리면 카드가 죽는 새 실패가 생긴다).
  - 이동할 때 선택을 풀지 않는다. 뒤로 오면 같은 지도 위치·핀 강조·카드·카테고리 필터가 그대로다.
  - 새 조회는 없다. 상세 조회는 기존 `MuklogDetailRoute`가, 복귀 반영은 기존 `useRefreshOnFocus`의 핀·위시 재조회(각 1회)가 맡는다. 삭제된 기록이면 기존 `clearSelectionWhenPinGone`이 카드를 닫는다.
- 테스트
  - `SelectedSpotCard.spec.tsx`: 기존 7건에 SC1~SC12를 더했다(버튼 이름·힌트·호출 1회·쉐브론·버튼 1개·패딩이 버튼에 있는지·표면에 패딩이 없는지·감소 모션이 꺼졌을 때 transform이 붙는지·정적 opacity 경고 0건).
  - `MapTabScreen.spec.tsx`: MT1~MT9를 더했다(상세 이동 인자, 선택이 바뀐 뒤의 대상, 연타, 조회·주입 수 불변, 복귀 시 재조회·필터 유지, 편집 반영, 삭제 시 카드 닫힘, 주변·위시 카드 제외, 핀 오류·로딩 시 경로 없음). 네비게이션 더블은 `navigate`만 가져서 `push`로 바꾸면 TypeError로 실패한다.
  - `MapTabScreen.integration.spec.tsx`: 네비게이션 모킹만 추가했다.
- `docs/design/architecture.md` — §4 지도 탭 설명과 MuklogDetail 진입 경로, §5 스프린트 표에 `map-pin-card-detail` 행을 더했다.
- `docs/ux/ux-backlog.md` — U11을 완료로 바꾸고 후속 U64·U65·U66을 추가했다(§4).
- 공용 UI 패턴 라이브러리 조회(`feSkills.mjs find`): press-feedback 후보만 해당돼 판단값(카드 등급 축소·흐림, 감소 모션 시 흐림만)을 참고했다. page-transition은 네이티브 스택 전환을 쓰므로 채택하지 않았다.

## 5. 주의사항

- `SelectedSpotCard`의 `onPress`는 선택 prop이다. 새 소비처가 넘기지 않으면 조용히 비탭 카드가 된다. 필수로 바꾸려면 타입의 `?`를 지우고 카드 spec의 비탭 케이스에 `onPress`를 넘기면 된다.
- 연타 방지는 react-navigation 7의 `navigate` 동작(맨 위가 같은 이름이면 params만 갱신)에 기댄다. `push`로 바꾸거나 상세에 `getId`를 주면 여러 장 쌓일 수 있다. 단위 테스트는 더블이 `navigate`만 가져서 `push`를 막는다.
- 지도 진입 직후 곧바로 상세로 갔다 오면, 그사이 더 정밀한 현재위치가 도착했을 때 기존 자동 보정이 지도를 내 위치로 옮길 수 있다(계획상 허용한 기존 동작).
- 카드 너비 중 본문 폭이 22pt 줄었다(375pt 화면 237 → 215pt). 긴 카테고리 + 지역 메타는 더 일찍 말줄임된다(1줄 유지, 하트·`›`는 고정 폭).
