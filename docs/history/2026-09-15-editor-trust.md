## 1. 개요

장소와 별점만으로 기록을 저장할 수 있도록 메모를 선택 입력으로 바꾸고, 작성 중 실수로 뒤로 가도 입력을 보호한다. 이번 변경은 개발 코드에만 반영했으며 스토어 및 OTA 배포는 하지 않았다.

## 2. 작업 내용

- 작성·편집의 공통 검증과 화면을 장소·유효 별점 필수, 메모 선택으로 통일했다. DB의 NULL 별점과 기존 기록 조회는 구버전 호환을 위해 유지한다.
- 초기값 대비 실제 저장 필드 변경을 비교해 이탈 확인 시트를 표시한다. 검색 내부 복귀와 저장 성공 복귀를 구분하고 native-stack의 usePreventRemove에 연결했다.
- 저장 중 입력·중복 제출·이탈을 막고, 실패마다 토스트로 안내하면서 폼을 유지한다. 위시 후처리 대기 중 재제출도 막는다.
- 기존 Sheet 및 디자인 토큰을 재사용했다. fe-skills bottom-sheet(MIT) 정본을 조회했으며 새 의존성은 추가하지 않았다.
- UX 백로그 U8/U9/U16/U43 및 설계의 필수 입력 정책을 갱신했다.

## 4. 확인 필요 · 후속

- iOS 뒤로 스와이프는 조작 도구의 drag 유효성을 확인하지 못해 미검증이다. Android 하드웨어 뒤로가기, 키보드 열린 상태의 시트, 실서버 저장 실패·저장 중 제스처는 추가 디바이스 확인이 필요하다. 해당 상태의 자동 테스트와 실제 기기 검증을 동일시하지 않는다.
- 개인 기록을 변경하지 않기 위해 시뮬레이터에서 실제 저장·삭제를 실행하지 않았다. 성공/실패·저장 중 경합은 모킹된 Promise로 검증했다.
- 다음 순서: 상세 사진 전체화면·확대, 지역 검색·지도 카드 정보 개선.

## 5. 주의사항

앱 강제 종료 후 초안 복구, 오프라인 저장 큐, 서버 중복 저장 방지는 이번 범위가 아니다. DB/Edge Function/네이티브 의존성 변경 및 배포 없음. 미추적 사용자 설정 파일은 PR에 포함하지 않는다.
