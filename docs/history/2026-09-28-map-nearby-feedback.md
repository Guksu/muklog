## 1. 개요

UX 백로그 U10을 처리했다(위반 원칙 3·10). 지도 탭의 주변 음식점 조회는 로딩·실패·결과 0건을 사용자에게 전혀 알리지 않았다. 문제는 네 가지였다.
- "이 지역에서 검색"을 누르면 버튼만 사라졌다.
- 조회가 실패해도 아무 표시가 없었다.
- 결과가 0건이어도 아무 표시가 없었다.
- 지도 SDK가 준비·오류 신호를 모두 보내지 않으면 로딩 안내가 영구히 남았다.

네 항목은 같은 화면·같은 성격이라 한 스프린트로 처리했다(분할 없음).

## 2. 작업 내용

기획 → 퍼블리싱 → 구현 → 독립 검증 3종(qa-logic·qa-visual·qa-ux) → 수정 1회 → 재검증 순서로 진행했다. 전 과정은 워크플로 1회로 실행했다.

- `src/features/map/components/MapResearchButton/` — 재검색 버튼(pill)에 상태를 더했다.
  - `state` prop: `Idle`·`Searching`·`Failed`. 기본값은 `Idle`이라 기존 모습 그대로다.
  - 검색 중: 스피너와 "검색하는 중이에요"를 보이고, 비활성·busy 상태가 된다.
  - 실패: "주변 음식점을 불러오지 못했어요 · 다시 시도" 한 줄로 바뀐다.
  - 문구는 `MAP_RESEARCH_COPY`로 내보낸다. 검색 중에도 흐리게 하지 않는다(지도 위에 뜬 흰 pill이 비쳐 보여 고장처럼 보이기 때문).
- `src/features/map/useNearbyPlaces/useNearbyPlaces.ts` — 버튼 상태와 조회 결과를 화면에 알린다.
  - `researchState`(`Hidden`·`Idle`·`Searching`·`Failed`)를 내보낸다.
  - `research()`가 결과(`Found`·`Empty`·`Failed`·`Skipped`)를 담은 Promise를 돌려준다. 모든 경로에서 정확히 한 번 끝나고, reject하지 않는다.
  - 자동 조회(선로딩·보정)는 검색 중으로 표시하지 않는다.
  - 기존 `researchAvailable` 식은 바꾸지 않고 별칭으로 남겼다.
  - QA 반영: 상태 갱신을 한 객체로 합쳤다. "검색 중 → 숨김 → 실패"처럼 버튼이 잠깐 사라졌다 다시 생기던 문제(스크린리더 포커스 유실)를 없앴다.
- `src/navigation/screens/MapTabScreen/MapTabScreen.tsx` — 새 상태를 화면에 연결했다.
  - 버튼 상태를 연결했다.
  - 사용자가 누른 조회가 0건이면 토스트 "음식점이 없어요. 지도를 옮겨보세요"를 한 번 띄우고 스크린리더로 알린다. 자동 조회 0건은 알리지 않는다.
  - 사용자가 누른 조회가 실패하면 스크린리더로 한 번 알린다.
  - 지도 준비 제한 시간 `MAP_BOOT_TIMEOUT_MS`(10초)를 두었다. 마운트당 한 번만 도는 타이머이고, 준비·오류 신호가 오거나 화면이 사라지면 끝난다. 만료되면 기존 지도 오류 안내("지도를 불러오지 못했어요" + 다시 시도)로 합류하고, 늦게 준비 신호가 오면 저절로 복구된다.
  - 지도 가운데 안내(로딩·지도 오류·핀 오류)가 있으면 재검색 버튼을 숨긴다(새 우선순위 규칙). 하단 권한 배너와 상단 버튼은 함께 보일 수 있다.
  - 버튼 래퍼에 좌우 여백 16을 두었다(글자 크기를 키운 기기 대비, 기본 크기에서는 화면 변화 없음).
- `src/components/MotionPressable/MotionPressable.tsx`(앱 공용) — 버튼이 비활성으로 바뀔 때 눌림 애니메이션 값을 평상으로 되돌린다(`resetPressOnDisable`). 누른 직후 비활성이 되면 스프링이 멈춰, 다시 활성화될 때 축소된 모양이 남는 앱 전역 버그가 있었다(qa-visual QV-1). `Button`의 loading 뒤 재활성화도 같은 원인이었고 함께 고쳐졌다(QV-3).
- `src/features/map/types/` — `NearbyResearchState`·`NearbyResearchOutcome` enum을 추가했다.
- `src/features/map/nearbyTrace/` — 개발 모드 계측 이벤트 `map:boot-timeout`을 추가했다.
- `src/navigation/screens/MapTabScreen/MapTabScreen.integration.spec.tsx`(신규) — 실물 훅과 실물 화면을 함께 돌려 버튼 요소가 상태 변화 중 유지되는지 잠근다.
- `docs/design/architecture.md` — §4 지도 탭 화면 설명, §5 `map-pin-loading`·`map-feedback` 행의 대체 표기와 새 행, §6 비용 가드레일("지도 준비 제한 시간은 마운트당 1회성 타이머, 실패·0건 뒤 자동 재조회 0")을 반영했다.
- `docs/ux/ux-backlog.md` — U10을 완료로 바꾸고, 후속 U62·U63을 추가했다(§4).
- 공용 UI 패턴 라이브러리 조회(`feSkills.mjs find`): loading-button 후보를 참고했다. 최소 표시 시간(400ms)은 새 타이머가 필요해서 채택하지 않았다.

## 4. 확인 필요 · 후속

- **U62 — 지도 오류 뒤 "다시 시도"가 실제로 복구하지 못한다 (사용자 결정 필요).** 이번 제한 시간 만료도 기존 지도 SDK 오류와 같은 재시도로 합류한다. 그런데 그 재시도는 SDK가 없는 페이지를 되살리지 못해서, 늦은 준비 신호나 앱 재시작으로만 풀린다(qa-ux UX-1). 이번 변경 전에는 로딩이 영구히 남았으므로 나빠진 것은 아니다. 다만 동작하지 않는 버튼이 보인다.
  - 선택지 ①: 재시도 때 지도 WebView를 다시 불러온다(탭당 카카오 SDK 요청 1회).
  - 선택지 ②: 버튼 대신 "앱을 다시 열어 주세요"로 안내한다.
  - 권장은 ①이다. 사용자가 누를 때만 1회 요청하므로 폴링이 아니다.
- **U63 — 즉시 실패하는 재시도의 피드백, 응답이 멈춘 조회 (후속).** 오프라인처럼 바로 실패하면 "검색하는 중이에요"가 몇 ms만 보여 다시 시도했는지 알기 어렵다(qa-ux UX-2). 응답이 멈추면 OS 제한 시간(약 60초)까지 검색 중으로 남는다(D11). U39(오프라인 문구)와 함께 설계한다.
- **디바이스 확인 (출시 전, 담당: 사용자).** 검색 중 표시(느린 네트워크), 조회 실패 → 다시 시도, 지도 SDK 무응답 10초 만료와 늦은 복구, 375pt(iPhone SE) 배치, VoiceOver·TalkBack 낭독과 버튼 포커스 유지를 확인하지 못했다. 절차는 Network Link Conditioner나 네트워크 차단이 필요하다.
- **참고(범위 밖)**
  - 320pt(iPhone SE 1세대)에서 0건 토스트가 현재위치 버튼 왼쪽 약 18pt를 2.2초 가린다.
  - 하단 인셋 0 기기에서는 권한 배너 "설정 열기" 아래쪽 약 5pt를 가린다(QV-5, 수용).
  - 지도 탭 토스트 공통 폭 규칙("토스트 폭 ≤ 화면 폭 − 124")을 두면 기존 설정 열기 실패 토스트의 겹침도 함께 정리된다.
  - 검색 중으로 바뀔 때 눌림 축소가 한 프레임에 풀린다(QV-2).
  - 검색 중에 지도를 멀리 옮긴 뒤 0건이 오면 토스트가 지금 보이는 지역을 말하는 것처럼 읽힌다(UX-12).
  - 스크린리더 사용자가 카카오 지도를 끌어 옮길 수 있는지는 확인하지 않았다(UX-14).
- **Metro 개발 서버가 꺼져 있다.** 원래 떠 있던 서버가 작업 중 종료돼 있었다. 확인용으로 띄웠던 서버도 끝난 뒤 종료했으니, 시뮬레이터에서 앱을 쓰려면 다시 켜야 한다.

## 5. 주의사항

- `research()`는 이제 Promise를 돌려준다. 결과를 쓰지 않는 호출부도 reject가 없으므로 안전하지만, 새 호출부는 결과(`Found`·`Empty`·`Failed`·`Skipped`)로 분기한다.
- `researchAvailable`은 이전 식을 그대로 유지한 별칭이다. 화면은 `researchState`만 읽는다. 둘이 잠깐 어긋나는 좁은 경우(검색 중에 자동 조회가 캐시 적중하면서 크게 이동)가 있지만, 화면은 `researchAvailable`을 읽지 않아 영향이 없다.
- `MotionPressable` 변경은 앱의 모든 눌림 요소에 적용된다. 비활성 전환 시에만 값을 되돌리므로 평상시 동작은 같다.
- 0건·실패 토스트 문구는 한 줄을 전제로 현재위치 버튼·권한 배너와의 겹침을 계산했다. 문구를 늘리면 다시 가린다.
- 지도 준비 제한 시간을 바꾸려면 `MAP_BOOT_TIMEOUT_MS`만 고친다. 재시도가 타이머를 다시 켜지 않는 것은 의도다(D9). 켜게 바꾸면 부팅 대기 중 핀 오류 재시도가 영구 로딩을 되살린다.
