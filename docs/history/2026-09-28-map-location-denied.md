| 항목 | 내용 |

## 1. 개요

UX 백로그 U7과 U13의 ③을 한 스프린트로 처리했다. 둘 다 "지도 탭에서 위치 권한이 거부됐을 때 사용자가 할 수 있는 일이 없다"는 같은 문제다(위반 원칙 3·5·10).
- 기존: 거부 안내가 행동 버튼·닫기 없이 지도 한가운데를 계속 가렸다.
- 기존: 현재위치 버튼은 거부 상태에서 눌러도 아무 반응이 없었다.

이번 작업 결과는 다음과 같다.
- 안내를 버튼 위 하단 배너로 옮겼다.
- 배너에 "설정 열기"와 닫기를 넣었다.
- 거부 상태에서 현재위치 버튼을 누르면 안내를 다시 보여 준다.
- 설정에서 허용하고 돌아오면 앱을 다시 켜지 않아도 반영된다.

## 2. 작업 내용

기획(sprint-planner) → 퍼블리싱(ui-publisher) → 구현(developer) → 독립 검증 3종(qa-logic·qa-visual·qa-ux) → 수정·재검증 순서로 진행했다. 전 과정은 워크플로 1회로 실행했다.

- `src/features/map/components/MapPermissionBanner/`(신규) — 거부 안내 배너 컴포넌트.
  - 구성: 문구, "설정 열기" 버튼(`Button` soft sm), 닫기 버튼(44×44 터치 영역).
  - 비주얼: 킷에 권한 배너 정의가 없어서 기존 지도 상태 안내(`MapStatusOverlay`)의 스킨을 따랐다(흰 면·헤어라인·카드 radius·`shadow.md`).
  - 닫기 X 색: 킷의 보조 X 톤(대비 약 2.1~2.8:1) 대신 `fgWeak`(대비 약 7.3:1)를 썼다. 배너를 닫는 유일한 수단이라 아이콘 대비 기준(3:1)을 우선했다.
  - 문구 줄바꿈: iOS에서 글자가 아니라 어절 단위로 끊기게 `lineBreakStrategyIOS="hangul-word"`를 썼다. 이 코드베이스에서 처음 쓰는 속성이다.
  - 접근성: 두 버튼 모두 role button과 라벨을 두고, "설정 열기"에는 힌트를 붙였다. 배너 루트에는 `accessibilityLiveRegion="polite"`를 두었다.
- `src/features/map/components/MapLocateButton/` — 버튼 크기 46을 `MAP_LOCATE_BUTTON_SIZE` 상수로 내보냈다. 배너 위치 계산에 쓰며, 화면 모양은 바뀌지 않는다.
- `src/navigation/screens/MapTabScreen/MapTabScreen.tsx`
  - 거부 안내를 중앙 오버레이에서 빼서 하단 배너로 옮겼다. 위치는 `bottom = 16 + 버튼 크기 46 + 10`이고, 좌우 여백은 16이다.
  - 로딩·지도 오류·핀 오류 안내가 지도 가운데에 떠 있으면 배너는 숨긴다(기존 우선순위 유지).
  - "설정 열기"는 `expo-linking`의 `openSettings()`를 호출한다(기존 의존성). 실패하면 토스트로 알리고, 배너는 닫지 않는다.
  - 닫기 상태는 화면 상태에만 두고 저장하지 않는다. 거부 상태에서 현재위치 버튼을 누르면 배너가 다시 보이고 스크린리더가 안내 문구를 읽는다. 이때 위치 호출은 0회다.
- `src/features/map/useLocationPermission/useLocationPermission.ts`
  - 거부 상태일 때만 AppState `active`(앱이 다시 앞으로 올 때 오는 1회성 신호)에서 권한을 기기 로컬로 1회 다시 조회한다(`getForegroundPermissionsAsync`).
  - 허용으로 바뀌었으면 기존 권한 요청 경로와 같은 좌표 취득 절차를 밟는다(OS 캐시 1회 + 정밀 위치 1회). 이 절차는 `acquireCoordsAfterGrant`로 뽑아 두 경로가 함께 쓴다.
  - 폴링·타이머는 없다. 동시 재조회 1회 가드가 있고, 거부를 벗어나거나 화면이 사라지면 리스너를 해제한다.
- `docs/design/architecture.md` — §4 지도 탭 화면 설명, §5 `map-locate-button` 행(거부 분기 대체), §6 비용 가드레일("OS 권한 상태 재확인은 폴링하지 않는다")에 반영했다.
- `docs/ux/ux-backlog.md` — 상태를 갱신하고 후속 항목을 추가했다.
  - U7: 완료. U13: ③ 완료, ①②는 대기.
  - U44: PR #33(메모 키보드)으로 해결됐는데 "대기"로 남아 있어서 완료로 고쳤다.
  - 후속 항목 U60·U61을 추가했다(§4).
- 리더 최종 수정(QA 판단 항목):
  - 설정 열기 실패 토스트 문구를 줄였다(qa-visual QV-2). 기존 문구는 375·402pt 폭에서 두 줄이 되어 배너의 "설정 열기" 버튼을 가렸다(iPhone SE에서 버튼 높이의 73%).
    - 기존: "설정을 열지 못했어요. 기기 설정에서 위치를 허용해 주세요"
    - 변경: "설정을 열지 못했어요. 설정 앱에서 허용해 주세요"(약 268pt, 한 줄)
  - "설정 열기" 힌트의 동사를 배너·토스트와 같은 "허용"으로 맞췄다(qa-ux X4).
    - 변경: "기기 설정에서 위치 권한을 허용할 수 있어요"
  - 주석의 옛 킷 줄 번호를 고쳤다(qa-visual 참고). 현재위치 버튼은 `mk-home.jsx:362-372`, 펄스 링은 `:340-342`다.

모든 jest 실행에 워크트리 제외 옵션을 붙였다. 병렬 세션이 만든 `.claude/worktrees/`(자체 `node_modules` 포함)가 jest 모듈 맵을 오염시켜 기본 실행이 시작 전에 실패하기 때문이다(`2026-09-28-memo-keyboard.md` §3과 같은 원인). 설정 수정은 별도 세션에서 진행 중이다. 같은 이유로 작업 종료 시 검증 훅의 기본 `npm test`는 이번 변경과 무관하게 실패한다.

**iOS 시뮬레이터 확인** (iPhone 17 Pro / iOS 26.4, 기존 Dev Client + 최신 Metro 코드, 가상 위치 서울시청 부근)

| 항목 | 결과 |
|------|------|
| 거부 상태 진입 | 지도 한가운데가 아니라 현재위치 버튼 바로 위에 배너가 뜬다. 버튼·필터바·범례와 겹치지 않는다. 문구는 두 줄("…볼 수 / 있어요"), 어절 단위로 끊김 |
| 닫기 수명(D7) | 닫기 → 먹로그 탭 갔다 오기 → 계속 숨김 → 현재위치 버튼 탭 → 배너 다시 보임 |
| 설정 열기 | 설정 앱이 열리고 상단에 "◀ 먹로그" 복귀 링크가 있다. **다만 앱 설정 페이지가 아니라 설정 첫 화면이 열렸다**(두 번 모두). 앱은 OS 표준 경로(`openSettings`)만 호출하므로 시뮬레이터 동작일 가능성이 있다. 실기기 확인 필요(§4) |
| 권한 그대로 복귀 | 배너 유지, 앱 재시작 없음 |
| 거부 → 허용(D1) | 설정 → 앱 → 먹로그 → 위치 → "앱을 사용하는 동안" → 복귀. 배너가 사라지고 내 위치 점이 표시됐다. 앱 프로세스 번호가 같아(재시작 없음) 복귀 시 재조회가 반영한 것을 확인 |
| 허용 → 거부, 앱 실행 중(D4) | 앱 재시작 없음. 내 위치 점이 남고 배너도 뜨지 않는다. 계획에서 범위 밖으로 둔 알려진 한계와 같다(U60) |
| 서버 데이터 | 조회만 했다. 기록·위시 변경 0건 |

확인을 위해 시뮬레이터의 먹로그 앱 위치 권한을 `simctl`로 거부·허용했다. 끝난 뒤 허용 상태로 되돌렸고, 가상 위치는 서울시청 부근으로 두었다.

## 4. 확인 필요 · 후속

- **"설정 열기"가 앱 설정 페이지로 가는지 실기기 확인 (출시 전, 담당: 사용자).** iOS 26.4 시뮬레이터에서는 설정 첫 화면이 열렸다. 실기기에서도 같다면 사용자가 앱 → 먹로그 → 위치를 직접 찾아야 한다. 그 경우 배너 힌트나 실패 토스트 문구에 경로를 더 구체적으로 적을지 결정이 필요하다(기본값: 현행 유지).
- **Android 확인 (출시 전, 담당: 사용자).** 아래 항목은 이 환경에서 확인하지 못했다.
  - 한 번 거부·"다시 묻지 않음" 각각에서 거부 → 허용(D2), 설정에서 권한 회수 후 복귀(D3).
  - 360dp에서 배너 줄바꿈. Android는 어절 단위 줄바꿈 속성이 없어 "…현재 위치 / 를 볼 수 있어요"처럼 끊길 수 있다.
  - 새로 마운트된 배너의 live region 자동 낭독 여부.
- **스크린리더 확인 (담당: 사용자).** VoiceOver·TalkBack에서 두 버튼의 포커스·라벨·힌트, 거부 상태 버튼 탭 시 알림 낭독, 닫은 뒤 포커스 위치를 확인하지 않았다.
- **후속 백로그로 등록한 것.**
  - U60: 앱이 켜진 채 허용→거부가 반영되지 않는다(D4).
  - U61: 설정에서 "다음번에 묻기"·"매번 묻기"를 고르고 돌아오면 다시 물어볼 길이 없다(qa-ux X1).
- **선택 후속(qa-logic 제안).** 실물 권한 훅과 실물 화면을 함께 돌리는 통합 테스트가 저장소에 없다. 허용 뒤 주변 조회 1회, 재센터 2회(OS 캐시 → 정밀) 같은 동작은 QA 프로브로만 확인됐다. 필요하면 프로브를 spec으로 옮긴다.
- **범위 밖 관찰.** 앱 전체의 다른 여러 줄 한글 문구도 iOS에서 글자 단위로 끊긴다. `lineBreakStrategyIOS`를 앱 전체로 넓힐지는 별도 결정이다.
- **시뮬레이터 Dev Client가 오래됐다.** 9월 12일 빌드라 위치 권한 설명이 옛 영문 기본 문구("Allow muklog to access your location")로 보인다. `app.json`에는 이미 한국어 문구가 있어(PR #31) 출시 빌드에는 문제없다. 필요하면 Dev Client를 다시 빌드한다.

## 5. 주의사항

- 배너 위치는 현재위치 버튼 크기 상수(`MAP_LOCATE_BUTTON_SIZE`)로 계산한다. 버튼 크기를 바꾸면 배너도 따라 움직이니 숫자를 직접 쓰지 않는다.
- 권한 재조회 리스너는 거부 상태에서만 존재한다. 허용 상태에서도 재조회가 필요해지면(U60) 비용 가드레일(로컬 조회 1회, 폴링 금지)을 그대로 지킨다.
- `useLocationPermission`의 좌표 취득 절차는 `request()`와 재조회가 공유한다. 한쪽만 바꾸면 두 경로 동작이 달라지니 `acquireCoordsAfterGrant`를 고친다.
- 실패 토스트 문구는 한 줄(375pt 폭에서 약 268pt)을 전제로 배너와 겹치지 않게 맞췄다. 문구를 늘리면 다시 배너를 가린다.
