## 1. 개요

사용자 요청: "출시 전 마지막으로 디자인·기능·사용성을 점검. 레퍼런스는 토스·당근·캐치테이블. 페르소나는 20~40대 커플 혹은 여성. 이 사용자를 모아 광고 수익을 노린다. 이 점을 고려해 개선 사항을 분석." 2026-08-23 UX 감사(U1~U70)를 덮어쓰지 않고, 기존 7축에 페르소나(P)·레퍼런스 갭(R)·성장·수익화(G) 렌즈를 더해 재감사했다. 코드 변경은 없고 산출물은 백로그 갱신뿐이다.

용어: **OTA** = 심사 없이 JS만 무선 배포 / **스토어 축** = 네이티브 변경이라 버전 올림·심사 / **계측** = 사용자 행동을 이벤트로 남겨 수치로 보는 것 / **DAU** = 하루 순 사용자.

## 5. 주의사항

- 백로그의 새 항목 근거 파일:라인은 **`3cf876f` 스냅샷 기준**이다. 이후 커밋에서 줄이 밀릴 수 있으니 착수 시 재확인한다.
- 수익·비용 수치는 전부 추정이다(eCPM $0.5~2, 사진 1장 0.35MB 등). 실측이 생기면 백로그 재감사 절 머리말의 수치를 갱신한다.
- 재감사는 코드·킷 읽기 근거이고 실기기 실행은 없었다. 특히 U71(WebView 종료)·U73(붙여넣기 잘림)은 라이브러리 원본·RN 동작 근거이며 실기기 재현은 착수 스프린트에서 한다.
- 브랜치 보호 훅(`branchGuard`)은 `CLAUDE_PROJECT_DIR`(원본 체크아웃, main) 기준으로 판정해 워크트리가 다른 브랜치여도 Write/Edit 도구를 막는다. 이번 문서 편집은 Bash 스크립트로 했다. 훅이 `input.cwd`(워크트리)를 우선 보게 고치는 것을 권한다.
