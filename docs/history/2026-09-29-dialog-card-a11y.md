## 1. 개요

iOS 시뮬레이터의 접근성 트리(화면 읽기 기능이 보는 요소 목록)에서 닉네임 변경 대화상자의 컨트롤이 하나로 합쳐져 있었다. 입력란·지우기·취소·저장이 "닉네임 닉네임 지우기 취소 저장"이라는 요소 하나로 노출됐다. 좌표 탭은 정상이었다. 하지만 VoiceOver(iOS 화면 읽기 기능) 사용자는 각 컨트롤을 따로 조작할 수 없었다.

원인은 카드 래퍼였다. 카드는 빈 `onPress`를 단 `Pressable`(누름 컴포넌트)이었다. 카드 안을 탭해도 딤(대화상자 뒤 반투명 배경)의 닫기가 실행되지 않게 하려는 용도였다. `Pressable`은 기본값이 접근성 요소다. iOS는 접근성 요소의 자식을 따로 노출하지 않는다. 같은 구조를 쓰는 대화상자 세 곳을 함께 고쳤다: 닉네임·로그 이름 변경, 업데이트 권유, OTA(스토어 심사 없이 앱의 JS를 바꾸는 배포) 적용 안내.

착수는 2026-09-28이다. 사용자가 원인·기대 결과·검증 방법을 직접 명세한 버그 수정이라 기획 단계(plan.md)는 두지 않았다. 계약은 인계 메모(dev-notes)의 인수조건 표로 대신했다. 구현은 한 명이 하고, 검증은 독립 QA 두 차례로 했다.

## 2. 작업 내용

- **카드 `Pressable` → `View` (3곳)** — `RenameDialog.tsx` · `UpdateSuggestModal.tsx` · `OtaReadyDialog.tsx`. 빈 `onPress`를 없앴다. `testID`와 스타일 배열은 그대로 뒀다. 스타일 값 변경은 0줄이다. 딤은 계속 `Pressable`이라 세 파일의 `Pressable` import는 그대로 쓰인다.
- **`accessible={false}`만 주지 않은 이유** — `Pressable`은 `focusable`도 기본 true로 넘긴다. Android는 `focusable`인 뷰에 클릭 리스너를 단다(`ReactViewManager.setFocusable`). 그러면 TalkBack(Android 화면 읽기 기능)이 카드를 "활성화할 수 있는 요소"로 잡는다. `accessible`만 끄면 iOS만 고쳐진다.
- **터치를 흡수하는 핸들러(`onStartShouldSetResponder`)를 붙이지 않은 이유** — 딤은 카드의 조상이 아니라 형제 레이어다. 터치는 손가락 아래 맨 위 뷰와 그 조상에게만 간다. 그래서 카드 위 터치가 딤에 닿을 경로가 없다. `Sheet`도 딤과 패널이 형제인 같은 구조다(패널에는 JS 누름 처리기가 없고 드래그 제스처만 따로 붙어 있다). 시뮬레이터에서도 확인했다. 핸들러를 붙였다면 없애도 동작이 같으므로 테스트로 잠글 수 없는 코드가 된다.
- **테스트 헬퍼 신설** — `src/test/findAccessibleAncestors`. 요소의 조상 가운데 접근성 요소를 찾아 이름표 배열(testID, 없으면 호스트 타입 이름)로 돌려준다. RNTL(React Native 테스트 라이브러리)의 `getByRole`·`getByLabelText`는 iOS의 "자식 가림"을 흉내 내지 않는다. 그래서 조회가 성공해도 개별 조작이 가능하다는 증거가 되지 못한다. 헬퍼 자체 spec 9건으로 실제 `Pressable`·`View`에서 판정이 맞는지 고정했다. 헬퍼가 판정하지 않는 것(호스트 `Text` 조상, 숨김 속성, Android 규칙)은 헤더 주석에 적었다.
- **대화상자 테스트 28건 추가** — 세 spec에 `dialog-card-a11y` 블록을 넣었다(10 + 10 + 8). 확인하는 계약은 다섯 가지다.
  - 카드가 접근성 요소도, 포커스·클릭 대상도 아니다.
  - 카드가 터치를 받는 뷰다(`pointerEvents`로 터치를 흘려보내지 않는다). 흘려보내면 실기기에서 카드 여백 탭이 딤으로 빠져 닫힌다.
  - 각 컨트롤의 조상에 접근성 요소가 없다.
  - 각 컨트롤이 자기 라벨·역할로 조회되고, 딤은 "닫기" 버튼으로 남는다.
  - 카드나 카드 안 제목을 탭해도 닫기 콜백이 불리지 않는다.
  기존 테스트의 단언은 수정하지 않았다(바뀐 기존 줄은 주석 1곳뿐).
- **jest 제외 패턴 수정(부수 작업)** — `package.json`의 `testPathIgnorePatterns`에서 `/\.claude/`를 `<rootDir>/\.claude/`로 바꿨다. `<rootDir>`는 jest가 프로젝트 루트 경로로 바꿔 넣는 자리표시자다. 이 작업 트리는 경로가 `…/.claude/worktrees/<이름>`이다. 그래서 기존 패턴에 모든 spec이 걸려 `npm test`가 "No tests found"(종료 코드 1)로 끝났다. 바꾼 패턴은 메인 체크아웃에서는 기존처럼 워크트리 사본만 거른다. 회귀 가드 `src/test/testPathIgnore/testPathIgnore.spec.ts` 5건을 추가했다. 이 가운데 1건은 실제 루트 경로로 확인한다. 루트 경로에 정규식 특수문자(괄호·더하기 등)가 있으면 패턴이 깨지기 때문이다.
- **문서** — `docs/testing-strategy.md`에 두 절을 추가했다: "워크트리에서 실행할 때"와 "접근성 단언". 뒤의 절에는 `toEqual` 대신 `toStrictEqual`로 빈 배열을 단언하라는 주의를 적었다. `toEqual`은 배열 안의 `undefined`를 무시하기 때문이다.
- **같은 패턴 검색** — 빈 `onPress`로 전파만 막는 누름 요소는 위 3곳이 전부다. `motion-press-sweep` 기록의 "전파차단 카드 3"과 일치한다. `Sheet` 패널과 `PhotoViewer`는 해당 없다. 누름 요소가 다른 조작 요소를 감싼 곳은 `CodeInput.tsx:32` 하나다. 성격이 달라 손대지 않았다(§4). 두 차례 QA도 독립적으로 전수 검색해 같은 결론을 냈다.
- **fe-skills 조회** — 패턴 라이브러리의 `modal-dialog` 후보를 확인했다. 웹 정본의 판단값(딤 클릭은 대상 기준으로 판정, 접근성은 플랫폼에 맡김)과 충돌하지 않는다. 조회는 구현 뒤에 했다. 버그 수정이라 패턴 구현으로 보지 않았는데, 순서상 먼저 했어야 한다.

**미검증**

- Android 실기기·에뮬레이터(TalkBack). `focusable` 계약은 jest로만 잠갔다.
- 구 아키텍처 iOS 바이너리. `app.json`은 `newArchEnabled: false`이고 스토어 빌드가 이쪽이다. RN 소스(`RCTView.m`)로 같은 규칙임은 확인했지만 실측은 하지 못했다.
- 실제 VoiceOver 음성 출력과 읽는 순서. 시뮬레이터에는 VoiceOver가 없어 접근성 트리와 활성화 경로까지만 확인했다.
- 실제 앱 흐름(프로필 → 닉네임 편집). 워크트리에 환경 변수 파일이 없고 읽지도 않았다. 그래서 로그인 없이 대화상자만 띄우는 임시 화면으로 확인했다. 컴포넌트와 props 형태는 실제 소비처와 같다.

## 4. 확인 필요 · 후속

- **브랜치 전환과 커밋(사용자)** — 커밋 전에 `fix/dialog-card-a11y`로 전환한다. 파일은 경로를 지정해 담는다. 워크트리 루트의 `.agents/` · `.codex/` · `AGENTS.md`는 이번 작업과 무관한 추적 안 된 파일이다. `.claude/hooks/verifierGate.state.json`도 종료 검증 훅이 자동으로 고친 상태 파일이다. 이번 작업 산출물이 아니므로 기본은 제외한다.
- **`package.json` 변경을 이 PR에 넣을지(사용자 결정)** — 테스트 환경 변경이라 성격이 다르다. 분리하려면 `package.json`, `src/test/testPathIgnore/`, `docs/testing-strategy.md`의 "워크트리에서 실행할 때" 절을 별도 커밋·PR로 나눈다. 결정하지 않으면 같은 PR에 커밋만 나눠 담는 것을 권장한다. 이 변경이 없으면 워크트리 안에서 `npm test`가 돌지 않는다.
- **실기기 확인(사용자, 다음 빌드 때)** — iOS VoiceOver와 Android TalkBack으로 세 대화상자를 연다. 컨트롤이 하나씩 읽히고 조작되는지 본다. JS만 바뀐 변경이라 OTA로도 배포할 수 있다.
- **가운데 정렬 대화상자의 VoiceOver "닫기"(1차 QA S-5, 기존 동작)** — 딤에는 `onAccessibilityTap`이 없다. 그래서 VoiceOver가 딤을 활성화하면 시스템이 대신 탭할 점을 고른다. 2차 재검증에서 시뮬레이터 런타임을 분석했다. 대신 탭하는 점은 프레임 중앙 한 점이 아니었다. 중앙·모서리 같은 후보를 히트 테스트해서 요소 자신이 맞는 첫 점이었다. 이 경로라면 카드가 중앙을 가려도 딤 모서리가 탭되어 닫힌다. 시뮬레이터 AXPress 관찰(닫힘)과도 맞는다. 다만 이것은 비공개 동작이다. 실기기 VoiceOver가 같은 경로를 쓰는지는 확인하지 못했다. 글씨를 크게 해 카드가 커지는 경우도 확인하지 못했다. 나중에·확인 버튼으로는 언제나 닫을 수 있다. 확실히 하려면 세 딤에 `onAccessibilityTap={닫기}`를 주는 후속 작업을 권한다. 그러면 좌표와 무관하게 닫힌다. 실기기 확인 절차: VoiceOver를 켜고, "닫기"에 초점을 둔 뒤 두 번 탭한다. 더 큰 텍스트를 최대로 해서 한 번 더 한다.
- **`CodeInput` 접근성(후속, 별도 세션 진행 중)** — `src/navigation/screens/CodeInput/CodeInput.tsx:32`의 포커스 캐처 `Pressable`이 숨김 입력란을 감싸고, 역할·라벨이 없다. 화면 읽기 기능에서 이름 없는 요소 하나로 잡힐 가능성이 높다. 기기 확인은 하지 않았다.
- **카드 그림자(2차 비주얼 QA, 기존 사항)** — iOS에서 카드 그림자(`shadow.dialog`)가 `overflow: 'hidden'` 때문에 잘려 보이지 않을 가능성이 소스상 높다. 이번 변경과 무관하다. iOS 실측 후 필요하면 ui-publisher가 "그림자 외곽 View + 클립 내부 View"로 나눈다. 나눌 때도 접근성 요소로 묶이지 않게 한다.
- **로그 카드 라벨(1차 QA S-6, 참고)** — `LogListScreen.tsx:211`의 `Card accessibilityLabel="로그 열기"`가 로그명·통계를 가린다. UX 백로그 후보다.
- **대화상자 제목 안내(후속 후보)** — 대화상자가 열릴 때 제목을 먼저 읽어 주는 처리(`accessibilityViewIsModal` 등)는 이번 범위가 아니다.

## 5. 주의사항

- 카드를 다시 `Pressable`·`Touchable` 계열로 만들지 않는다. 컨트롤 여러 개를 접근성 요소 하나로 감싸지도 않는다. 같은 결함이 돌아온다. 카드가 딤에 닿는 탭을 막아야 하면 딤과 카드를 형제 레이어로 유지한다.
- 카드에 `pointerEvents` `box-none`·`none`을 주지 않는다. 카드 여백 탭이 딤으로 빠져 대화상자가 닫힌다.
- 접근성 단언은 조회 성공(`getByRole` 등)만으로 끝내지 않는다. `findAccessibleAncestors`로 조상 사슬을 함께 확인하고, 빈 배열은 `toStrictEqual([])`로 단언한다.
- `testPathIgnorePatterns`에 `<rootDir>` 없는 `.claude` 패턴을 다시 넣지 않는다. 워크트리 세션의 테스트와 종료 검증 게이트가 전부 멈춘다.
- 시뮬레이터의 개발용 앱은 로컬 `ios/` 폴더 기준(새 아키텍처)이라 스토어 빌드와 아키텍처가 다르다. 네이티브 층 동작을 시뮬레이터에서 확인했으면 이 차이를 함께 적는다.
- 종료 검증 게이트는 멈출 때마다 전체 `npm test`를 돈다. 다른 세션이 jest를 많이 돌리는 중이면 이번 변경과 무관한 5초 제한 실패가 날 수 있다. 실패한 spec을 따로 돌려 부하 탓인지 먼저 가린다.
- 검증에 쓴 임시 파일(`metro.config.js`, 임시 검증 화면 폴더, `.expo/`)과 임시 시뮬레이터 기기는 모두 삭제했다. 접근성 트리 덤프 도구는 저장소에 넣지 않았다.
