## 1. 개요

1.3.0(App Store, 2026-09-01) 이후 main에 쌓인 33커밋을 스토어 릴리스로 낸다. 주요 내용은 지도 WebView 종료 복구(#45), 초대 공유 시트·붙여넣기(#46), 합류 알림·푸시 문구(#47), 장소 검색·메모 키보드 수정, 접근성 수정이다. 사용자가 같은 설정의 Android 미리보기 빌드(EAS `preview`, 구 아키텍처)로 실기기 확인을 마쳤고(2026-10-01, 문제 없음), 그 조건 그대로 낸다.

## 2. 작업 내용

- `app.json` `version` 1.3.0 → **1.4.0**. 1.3.0 이후 `app.json`의 위치 권한 키(`locationAlwaysAndWhenInUsePermission`·`locationAlwaysPermission` false)가 바뀌어, architecture §7 (B) 규칙상 네이티브 설정 변경 뒤 첫 스토어 릴리스는 버전을 올려야 한다. App Store도 승인된 1.3.0보다 높은 버전을 요구한다. `runtimeVersion` 정책이 appVersion이라 OTA 런타임도 1.4.0이 된다.
- `otaConfig.spec.ts`: 버전 단언을 1.4.0으로 갱신(먼저 실패 확인 → app.json 변경으로 통과).
- `docs/design/architecture.md`: §1 현재 버전 표기, §5 "출시 범위 / 후속"에 1.4.0 결정(구 아키텍처 유지, 새 아키텍처 전환은 1.5.0).
- `docs/ux/ux-backlog.md`: U74·U75·U28 완료 표기(PR #47, 운영 배포 2026-10-01).
- **사용자 결정(2026-10-01)**: ① 구 아키텍처(`newArchEnabled: false`) 유지 — 확인한 빌드와 같은 조건. 새 아키텍처 전환(2026-09-29 결정 B)은 1.5.0으로 미룬다(Expo SDK 54+ 업그레이드·Play API 36 요건·Android 첫 출시와 함께). ② 1.3.0 사용자 대상 OTA는 보내지 않는다(1.4.0 스토어 업데이트로 전달).
- **서버 쪽은 이미 운영 반영됨(2026-10-01)**: 마이그레이션 `20261001120000_join_push.sql` 적용(확인 SQL 통과), `send-join-push` v1 신규·`send-muklog-push` v2 배포(로그인 없는 호출 401 확인). 새 기록 푸시 문구는 1.3.0 사용자에게도 이미 적용됐다. 합류 알림은 앱이 새 함수를 불러야 하므로 1.4.0부터 동작한다.

## 4. 확인 필요 · 후속

**제출 절차(병합 뒤)**
1. iOS 프로덕션 빌드: `npx eas-cli build --platform ios --profile production`(빌드 번호는 EAS가 자동 증가).
2. App Store Connect 업로드: `npx eas-cli submit --platform ios --latest`.
3. (권장) TestFlight로 아이폰 확인 — iOS에서는 이번 변경을 실기기로 확인하지 않았다(공유 시트 취소 뒤 재공유, 붙여넣기 허용 창, iPhone SE 이름 변경 다이얼로그).
4. App Store Connect에서 "이번 버전의 새로운 기능"을 넣고 심사 제출(사용자).
5. 승인·출시 뒤: `app_config.latest_version`을 `1.4.0`으로 올려 1.3.0 사용자에게 업데이트 권유를 띄운다(콜드스타트 1회 조회 — 비용 변화 없음).

**후속**: 1.5.0 = 새 아키텍처 전환 + Expo SDK 업그레이드 + Android 출시 준비(FCM·알림 채널·사진 권한 정책·Play 콘솔) + 크래시 리포팅(Sentry).

## 5. 주의사항

- 1.4.0부터 OTA 런타임이 1.4.0이다. 1.3.0 사용자에게 JS 수정을 보내려면 1.3.0 런타임 커밋에서 따로 발행해야 한다(이번에는 보내지 않음).
- Android는 이번에 스토어에 내지 않는다(Play 출시 요건 미충족 — 출시 전 점검 D17~D20).
