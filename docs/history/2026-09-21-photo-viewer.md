## 1. 개요

기록 상세의 사진을 눌러 전체 모습을 보고 1~3배로 확대하는 기능을 추가했다. 기존에는 상세 화면에서 잘린 사진만 볼 수 있었다. 사용자 요청에 따라 실제 iOS 시뮬레이터 화면과 자동 테스트를 함께 검증하며, 손가락 제스처와 Android 실기기 확인은 별도로 구분한다.

## 2. 작업 내용

- 상세의 실제 사진을 누르면 해당 사진부터 전체화면으로 연다. 사진 없는 음식 커버는 열기 대상에서 제외한다.
- 전체화면은 사진 전체가 들어오는 크기로 표시한다. 닫기·사진 번호·이전/다음·확대/축소 버튼은 사진과 분리해 고정한다.
- 기존 Gesture Handler와 Animated로 사진 넘기기, 1~3배 확대, 확대 사진 이동을 구성한다. 확대 중에는 드래그로 다음 사진을 넘기지 않는다.
- 뷰어를 다시 열거나 사진을 바꾸면 확대 상태를 초기화한다. 열린 동안 사진 배열을 고정하고 이미지 로딩·실패 안내를 제공한다.
- 검정 배경과 흰 글자를 기존 팔레트에서 미디어 전용 토큰으로 정의한다. 새 패키지와 서버 변경은 없다.
- fe-skills의 pinch-zoom·swipe-dismiss-viewer·zoom-lightbox 패턴(MIT)을 검토했다. 초점 유지와 프레임별 ref 갱신 원칙을 RN으로 적용했으며, DOM 코드와 손을 떼면 확대를 원복하는 피드 동작은 사용하지 않았다.

검증 중 취소된 스와이프의 페이지 이동과 사진 전환 애니메이션 중단 시 조작 잠금 가능성을 발견해 수정했다. 취소·회전·이미지 오류 후 다시 이동하는 회귀 테스트가 통과했다. 최초 전체 실행의 핀치 테스트 2건 실패는 테스트 환경에서 제스처 활성화 등록을 기다리지 않던 문제였다. 활성화 반영 후 입력하도록 테스트를 고친 뒤 전체 재실행이 통과했다. 기존 중복 mock 및 Animated act 경고는 남아 있다.

## 4. 확인 필요 · 후속

- 배포 전 iOS·Android에서 두 손가락 확대, 확대 중 이동, 손가락 수 전환, 여러 사진 넘기기를 직접 확인한다. 자동 조작 도구의 드래그가 시뮬레이터에서 변화를 만들지 못해 실제 제스처 통과로 판정하지 않았다.
- 현재 계정은 사진 한 장짜리 기록이므로 다중 사진 동작은 자동 테스트와 실제 기기 확인을 구분한다.
- Android 뒤로가기, 큰 글꼴·스크린리더, 회전 중 제스처 체감은 실기기 확인이 남는다.

## 5. 주의사항

이미지 주소는 상세에서 받은 기존 signed URL(일시 접근 주소)을 그대로 사용한다. URL 재발급·미리 불러오기·추가 Supabase/Kakao 호출은 없지만 캐시에 없는 이미지의 전송량은 발생할 수 있다. 확대는 원본의 해상도를 높이지 않는다. 기존 출시 버전에 배포하거나 OTA 업데이트를 발행하지 않는다.
