## 1. 개요

초대코드로 상대가 들어와도 초대한 사람에게 아무 신호가 없어, 커플이 성립하는 순간이 조용히 지나갔다(출시 전 재감사 A4·D9 → U74). 새 기록 푸시는 닉네임 없는 작성자일 때 "연인님이 새 맛집을 기록했어요 🍽️"로 나가 앱 안 이름("수달2847")과 갈리고 가게 이름도 없었다(A10 → U75). 저장·입장은 푸시 응답을 기다렸다(U28). 합류 알림을 새로 보내고 푸시 문구를 앱과 맞췄다.

용어: **Edge Function** = Supabase 서버에서 도는 작은 함수 / **claim** = 발송권을 DB에 한 번만 기록하는 것 / **fire-and-forget** = 호출하고 결과를 기다리지 않음 / **fail closed** = 확인할 수 없으면 보내지 않음.

## 2. 작업 내용

- **합류 알림(새 함수 `send-join-push`)**: 입장 성공 직후 앱이 fire-and-forget으로 부른다. 서버는 JWT의 사용자만 믿고, 그 사람이 그 로그의 멤버이고 생성자가 아니며 10분 안에 합류했을 때만, `claim_join_push`(한 문장 원자적 UPDATE)로 **합류 1건당 1회**만 보낸다. 수신자는 본인 제외 멤버, 기존 수신 설정(master·로그별)을 그대로 따른다. 문구: 제목 = 로그 이름(없으면 "우리 로그"), 본문 "{닉}님이 들어왔어요. 이제 함께 기록할 수 있어요." 탭하면 그 로그 화면.
- **구 함수와 분리한 이유**: 운영 중인 `send-muklog-push`는 모르는 필드를 무시해, 새 앱이 함수 배포보다 먼저 나가면 합류 때 "새 맛집을 기록했어요" 오발송이 난다(보안 QA가 실제 재현). 새 이름으로 분리해 미배포면 404 → 무발송. 공통 코드는 `_shared/`(http·pushDelivery·pushCopy·pushDeps·adminClient·defaultNickname 이식본·toPlainText·describeError).
- **새 기록 푸시(`send-muklog-push`)**: 본문 "{닉}님이 ‘{가게명}’ 기록을 남겼어요"(조사 없는 틀, 둥근 작은따옴표, 이모지 없음). 닉네임 폴백은 앱과 같은 `defaultNickname` 알고리즘(이식본 일치 테스트). `muklogId`가 그 로그의 호출자 작성 기록일 때만 보낸다(위조면 무발송). 출시본 1.3.0의 본문 `{ roomId, muklogId }`는 그대로 받는다.
- **마이그레이션 `20261001120000_join_push.sql`**: `room_members.join_push_claimed_at`(처음 만들 때만 기존 행 백필 → 소급 발송 0), 클라이언트의 `room_members` UPDATE 권한 회수, `claim_join_push`(SECURITY INVOKER, service_role 전용), **`list_room_push_targets` 실행 권한을 service_role로 한정**(기존에 기본 실행 권한이 회수되지 않아 클라이언트가 직접 부를 수 있던 상태를 닫음).
- **앱**: `triggerPush`(fire-and-forget, 합류는 `send-join-push` 이름으로만), `useCreateMuklog` 발송 대기 제거(U28), `notificationTarget`에 `member_joined`, 같은 로그 화면이 맨 위일 때 알림 탭을 `pushTapAt`으로 받아 멤버 1회 재조회(`useRefreshOnPushTap`), 로그 화면 재포커스 때 멤버 재조회, 커플 판정을 멤버 수 기준으로 통일.
- **리더 지시 추가 수정**: ① 멤버 재조회가 실패해도 이미 받은 목록 유지(`useOneShotQuery`에 기본 꺼짐 선택 옵션 `keepLastReady`, `useRoomMembers`만 켬), 한 번도 못 받았으면 제목은 `room.memberCount` 기반 폴백 ② 알림 문구 재료의 줄바꿈·제어·방향 제어·제로폭·채움 문자 정리와 앱 입력 상한(닉네임 20·로그 이름 20·가게명 60) 자르기, 정리 뒤 비면 폴백 ③ 서버 오류 로그는 code·message만(토큰·JWT·키 가림, 2000자로 먼저 자른 뒤 되돌아가기 없는 패턴) ④ 본문 ID를 UUID 형식으로 먼저 검사(아니면 400) — 긴 가짜 ID로 함수 CPU를 십수 초 잡던 정규식 지연(보안 QA 2차 S2-1) 해소.
- **기타**: `docs/ux/ux-backlog.md`에 이전 PR 완료 표기 7건(U71·U62·U72·U73·U37·U24·U23), `docs/design/architecture.md` §3·§4·§5·§6.

## 4. 확인 필요 · 후속

**배포(사용자 몫 — PR 병합은 배포가 아니다)**
1. **마이그레이션 먼저, 가능한 한 빨리**: `supabase db push`(또는 SQL 편집기에서 `20261001120000_join_push.sql` 실행). 푸시 대상 조회 함수 권한을 닫는 내용이 들어 있고, 운영 중인 함수·앱에 영향이 없다(구 함수는 service_role로 부름). 적용 직후 SQL 스모크:
   - `select count(*) from public.room_members where join_push_claimed_at is null;` → 0
   - `select has_function_privilege('authenticated', 'public.list_room_push_targets(uuid,uuid)', 'execute');` → false (anon도 false, service_role은 true)
   - `select has_table_privilege('authenticated', 'public.room_members', 'update');` → false
2. **함수 2개**: `supabase functions deploy send-join-push` → `supabase functions deploy send-muklog-push`(`_shared`를 함께 묶으므로 CLI 배포, 새 설정값 없음, `config.toml`의 `verify_jwt = true`는 CLI 배포 때 적용).
3. **앱 OTA**: architecture §7 (D). 네이티브·`app.json` 변경 없음.
4. 어느 단계가 늦어도 잘못된 알림은 없다(plan D7 10가지 경우 표 — 미배포 함수는 404 무발송, 마이그레이션 전 합류 알림은 fail closed).

**기기 스모크(두 계정)**: A 로그 생성 → 공유 → B 입장 → A에 합류 알림 1건, 탭하면 참여자 2명 / B가 같은 코드 재입력·A가 자기 코드 입력 → 알림 0 / 앱이 백그라운드인 채 같은 로그 화면에서 알림 탭 → 참여자 갱신·나가기 시트 커플 문구 / B 새 기록 → A에 "{B}님이 ‘{가게명}’ 기록을 남겼어요", 저장 직후 바로 돌아옴 / 알림 설정 끄면 둘 다 0 / 함수 로그에 토큰·JWT 없음.

**리더 결정(plan 질문 Q1~Q7 기본값 채택)**: 합류 제목 폴백 "우리 로그" / 조사 없는 문구 틀 / 알림 설정 토글 문구("새 먹로그 알림")는 이번에 안 바꿈 — 합류 알림도 같은 토글을 따르며, 종류별 토글(A18) 때 정리(킷 변경이라 사용자 확인 대상) / 권한 회수 포함 / 알림 탭 재조회 포함 / 합류 10분 창 / 새 기록 알림 반복 호출 1회 제한은 범위 밖.

**알려진 한계·후속**
- 새 기록 알림은 같은 기록 id로 반복 호출하면 반복 발송된다(기존 동작, 후속 B1 — 기록 테이블에 같은 방식 컬럼).
- 응답의 발송 수로 상대의 알림 끔 여부를 추정할 수 있다(R2 — 계약 변경 필요, 후속).
- 이번 권한 회수 전에 조회됐을 수 있는 푸시 토큰은 계속 유효하다 — Expo 푸시 보안 강화(액세스 토큰) 검토(B2).
- 탈퇴·재가입을 반복하면 합류 알림이 회차마다 간다(B3 로그별 상한, 선택).
- 문구 QA 관찰: 합류한 사람 화면에서 멤버 로드 전후로 제목 이름 순서가 바뀔 수 있고, 3명 이상 로그의 폴백 제목은 2명 꼴이다(홈 카드와 같은 기존 규칙).
- 푸시 대상 조회가 실패하면 로그 없이 빈 목록으로 처리된다(계약 "오류면 []") — 권한 문제 진단이 어렵다(후속 후보).
- seam 밖 예외로 잠근 테스트: `useOneShotQuery` 늦은 응답 경계·refresh 중 로딩 유지, `useRoomMembers` roomId 변경 재조회.

## 5. 주의사항

- 합류 알림을 `send-muklog-push`로 보내도록 바꾸지 않는다(구 함수 오발송). 앱은 합류를 `send-join-push` 이름으로만 부른다 — 테스트로 잠김.
- `_shared`를 고치면 두 함수를 모두 다시 배포한다.
- 셸 heredoc·python 인자를 거치며 `‮` 같은 이스케이프가 실제 보이지 않는 문자로 바뀔 수 있다 — 소스 수정 뒤 유니코드 범주 전수 검사를 한다.
- Deno 테스트는 저장소 루트의 위 명령으로 돌린다(진입점 `index.ts`를 import하지 않는 구조 — 네트워크 권한 불필요).
