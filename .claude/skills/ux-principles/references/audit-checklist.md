# UX 감사 체크리스트 — 7축 채점과 백로그 형식

전 화면 UX 감사(또는 특정 화면 재감사) 시 이 문서의 축과 형식을 그대로 따른다. 감사 주체는 화면 소스(`src/`)와 킷 시안(`templates/muklog`)을 **둘 다 열어** 비교하며 채점한다 — 소스만 보면 의도를, 킷만 보면 현실을 놓친다.

## 채점 7축

각 축은 SKILL.md 원칙 번호에 대응한다. 축마다 ✅(문제 없음) / ⚠️(개선 여지) / ❌(원칙 위반)으로 판정하고, ⚠️·❌는 근거(파일:라인 또는 재현 절차)를 남긴다.

| 축 | 보는 것 | 원칙 |
|----|--------|------|
| 1. 진입 마찰 | 주 과업까지 탭 수·필수 입력 수·기본값 선제공 여부 | 1·2 |
| 2. 인지 부하 | 화면당 과업 수, 한 번에 보이는 선택지 수, 정보 우선순위 | 1·6 |
| 3. 피드백·로딩 | pressed 상태, 스켈레톤/자리표시, 낙관적 UI, 무언 스피너 여부 | 3 |
| 4. 모션 | 상태 전이 설명 여부, 지속시간, 장식성 애니메이션 | 4 |
| 5. 카피 | 해요체·행동 동사·시스템 용어·구체 숫자 | 5 |
| 6. 스캔성·친밀감 | 리스트 셀 구조(썸네일+메타 2줄), 탭 영역, 누가/언제/어디 신호, 상대방 존재 | 6·7·8·9 |
| 7. 빈·에러 상태 | 빈 상태 CTA 유무, 에러 문구의 행동 안내, 복구 경로 | 10·5 |

## 감사 대상 화면 목록

`src/navigation/`(HomeTabs·AppNavigator·routes)에서 실제 라우트를 열거해 감사 시점의 전체 화면 목록을 만든다 — 이 문서에 화면 목록을 복제하지 않는다(내비게이션 소스가 단일 출처, 복제하면 드리프트).

## 산출물: `docs/ux/ux-backlog.md`

```markdown
# UX 개선 백로그
> 감사일: {YYYY-MM-DD} · 기준: ux-principles 스킬 {커밋/버전} · 대상: {화면 수}개 화면

## 화면별 채점 요약
| 화면 | 1.마찰 | 2.부하 | 3.피드백 | 4.모션 | 5.카피 | 6.스캔 | 7.빈·에러 |
|------|--------|--------|---------|--------|--------|--------|-----------|

## 개선 항목 (우선순위순)
| # | 화면 | 문제(근거 파일:라인) | 위반 원칙 | 개선안 | 임팩트 | 비용 | 킷 충돌 |
|---|------|---------------------|----------|--------|--------|------|---------|
```

- **임팩트**: 상(핵심 플로우·매 사용 노출)/중/하. **비용**: 상(구조 변경)/중(화면 내 수정)/하(카피·토큰 수준).
- **킷 충돌**: 개선안이 킷 시안 변경을 요구하면 `⚠️ 사용자 확인 필요`로 표기 — 이 항목은 스프린트 착수 전 사용자 승인 게이트를 거친다.
- 우선순위 기본 정렬: 임팩트↑ → 비용↓. 최종 순서는 사용자가 정한다.
- 재감사 시 기존 백로그를 덮어쓰지 않고 항목 상태(대기/진행/완료/보류)를 갱신한다 — 완료 항목은 감사 추적을 위해 보존.

## 감사 실행 형태 (오케스트레이터 참고)

- 화면 수가 많으므로 탭 영역 단위(홈/지도/기록·에디터/프로필·설정·인증)로 **서브 에이전트 1~3개 병렬** 팬아웃이 기본 — 각자 이 체크리스트 + SKILL.md + 담당 화면 소스 + 킷 시안을 읽고 채점 표를 반환, 리더가 병합해 백로그를 쓴다.
- 감사는 읽기 전용이다 — 감사 중 코드 수정 금지. 수정은 백로그 승인 후 개선 스프린트에서 한다.
