# muklog UX 원칙 — 토스·당근 레퍼런스

토스·당근에서 추출한 UX 판단 기준을 muklog(커플 맛집 기록 앱) 맥락으로 번역한 참조 스킬. **sprint-planner**(UX 개선 스프린트 기획·감사)와 **ui-publisher**(구현 중 마이크로 판단)가 사용한다.

## 위상 — 킷과의 관계 (가장 중요)

- **비주얼 단일 출처는 여전히 킷 `templates/muklog`다**(`.claude/skills/ui-design/templates/muklog/`). 이 스킬은 킷을 대체하지 않는다.
- 이 원칙들은 **킷이 침묵하는 영역**에서만 판단 기준이 된다: 화면 플로우·진입 단계 수, 로딩/피드백 전략, 모션, 빈·에러 상태, 카피 뉘앙스, 정보 우선순위.
- **충돌 시 킷 우선.** 원칙이 킷의 토큰·레이아웃·프리미티브 변경을 요구하면 임의 적용하지 않고 사용자에게 확인한다(하네스 절대 규칙 4). 승인된 킷 변경은 킷 파일에 먼저 반영한 뒤 RN에 번역한다 — 순서를 뒤집으면 단일 출처가 죽는다.

## 원칙 10 — 토스에서 (단순함·속도감)

1. **한 화면 = 한 가지 일.** 화면의 주 과업이 하나인지 본다. 두 과업이 섞이면(예: 기록 작성 + 장소 탐색) 분리하거나 단계로 나눈다. muklog는 이미 MuklogEditor 풀스크린·PlaceSearchView 스왑으로 이 방향이다 — 신규 화면도 같은 기준.
2. **진입 마찰 제거.** 목표 행동까지 탭 수를 센다. 기본값 선제공(오늘 날짜·현 위치·최근 카테고리), 선택 사항은 뒤로 미루기(progressive disclosure), 필수 입력 최소화. "기록 하나 남기기"가 3탭을 넘으면 의심한다.
3. **즉각 피드백.** 탭 즉시 반응(pressed 상태·햅틱), 기다림은 스켈레톤/자리표시로 예고, 성공은 낙관적 UI(먼저 반영, 실패 시 롤백+안내). 스피너만 띄우는 무언 로딩 금지.
4. **목적 있는 모션.** 모션은 상태 전이를 설명할 때만(어디서 왔고 어디로 가는지). 장식용 애니메이션은 넣지 않는다. 지속시간은 짧게(150~300ms), 제스처는 실기기 검증 필수(→ 시트 드래그 RNGH 교훈).
5. **말하듯 쓰는 카피.** 해요체, 사용자 행동 중심 동사("기록을 남겨보세요" > "기록 추가"), 시스템 용어 금지("오류 코드 401" ✗ → "다시 로그인해 주세요" ✓). 구체 숫자를 쓴다("맛집 12곳"). — 킷 카피 규칙과 동일 방향이므로 충돌 없음.
6. **숫자·핵심 정보의 타이포 위계.** 화면에서 사용자가 찾는 값 하나(별점·거리·개수)가 첫눈에 잡히게 크기·굵기 위계를 준다. 모든 텍스트가 같은 급이면 위계 실패.

## 원칙 — 당근에서 (친밀감·스캔성·신뢰)

7. **관계 친밀감.** muklog의 "동네"는 커플이다. 상대방의 존재를 UI에 드러낸다: 누가 남긴 기록인지(MemberBadge), 상대가 최근 남긴 것, 함께 간 곳 신호. 혼자 쓰는 앱처럼 보이면 실패.
8. **리스트 스캔 최적화.** 리스트 셀은 썸네일 + 핵심 메타 2줄(상호·카테고리/별점·날짜)로 3초 안에 훑을 수 있게. 셀 전체가 탭 영역. 무한 나열 대신 구분(날짜·지역) 헤더로 리듬을 준다.
9. **기록 신뢰 신호.** 언제·누가·어디서를 모든 기록 표면에 일관 노출. 사진이 없어도 초라하지 않게(FoodCover 폴백 — 킷의 음식커버가 이 역할).
10. **빈 상태 = 다음 행동 안내.** 빈 화면은 상태 설명이 아니라 CTA다: 무엇이 비었고, 지금 뭘 하면 되는지 버튼 하나로. "데이터가 없습니다" 금지.

## 사용법

- **UX 감사·백로그 작성**: `references/audit-checklist.md`의 7축으로 화면별 채점 → `docs/ux/ux-backlog.md` 표(형식은 체크리스트 문서에 정의) 작성·갱신.
- **개선 스프린트 기획**(sprint-planner): 백로그 항목의 "위반 원칙" 번호를 plan.md 인수조건에 인용 — 개선이 검증 가능해진다(예: "저장 시 낙관적 반영, 실패 롤백 토스트 — 원칙 3").
- **구현 중 판단**(ui-publisher): 킷에 답이 없는 마이크로 결정(로딩 표현·카피 다듬기·모션 지속시간)은 이 원칙 번호를 ui-spec.md에 근거로 남긴다.
- 원칙 위반을 발견해도 **킷 시안과 충돌하면 사용자 확인이 먼저다** — 위상 절 참조.
