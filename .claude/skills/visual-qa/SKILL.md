# Visual QA — 킷 시안↔RN 퍼블리싱 충실도 검증 가이드

"컴포넌트가 있는가"가 아니라 **킷 시안(디자인 정답지)과 실제 RN 퍼블리싱이 일치하는가**를 본다. muklog는 웹 JSX 킷(`templates/muklog`)을 RN으로 번역하므로, 번역 손실·임의 변경·토큰 우회가 비주얼 회귀의 주 원인이다.

## 디자인 단일 출처
- **킷 `templates/muklog`** (`.claude/skills/ui-design/templates/muklog/mk-*.jsx`) = 정답지.
- **`docs/sprint/{slug}/ui-spec.md`** = ui-publisher의 킷 라인↔RN 파일:라인 매핑. 검증 출발점.
- **생산자 self-check 체크리스트**: `.claude/skills/ui-publishing/SKILL.md` §5(비주얼 충실도 체크리스트). ui-publisher가 모듈 완성마다 self-check한 항목을 **검증자 입장에서 재확인**한다(단일 출처 — 여기에 중복 정의하지 않는다).

## 왜 코드 리뷰/타입체크로 못 잡나
- 컴파일·테스트 통과 ≠ 시안 일치. radius 14를 16으로, 헤어라인을 그림자로 바꿔도 빌드는 통과한다.
- "토큰을 썼는가"와 "**맞는** 토큰을 썼는가"는 다른 검증이다.
- 킷 JSX를 안 보고 RN만 보면 "그럴듯하지만 시안과 다른" 화면을 통과시킨다 → **반드시 양쪽을 같이 연다.**

## 검증 방법: 킷과 RN을 같이 열기
ui-spec.md 매핑을 따라 킷 함수(`mk-home.jsx MapScreen` 등)와 대응 RN 파일을 동시에 펼쳐 3축으로 대조한다.

### ① 레이아웃·구조 / safe-area
- [ ] 요소 배치·계층·순서·정렬이 킷과 동일(헤더 워드마크, 카드, 하단 CTA, 오버레이 z-순서)
- [ ] flex 방향·gap·padding 구조가 킷의 레이아웃과 대응
- [ ] safe-area/edges 처리가 올바름(top/bottom inset 이중 적용·누락 없음 — SubBar 패턴 주의)
- [ ] 스크롤/고정 영역 구분이 킷과 일치

### ② 비주얼·토큰
- [ ] 색은 원티드 토큰 경유(`theme/`), **raw hex/rgb 0건** (`grep -rn "#[0-9a-fA-F]\{3,6\}" src/` 적발)
- [ ] 브랜드 파랑 `#3366FF`(primary 토큰)·강조색이 킷과 일치
- [ ] radius = 10(컨트롤)/16(카드) 등 킷 값과 일치(raw 숫자 아님)
- [ ] 스페이싱이 4px 그리드(`theme.spacing`) 경유, 킷 간격과 대응
- [ ] **그림자 아님 — 헤어라인 보더**(킷 규칙). RN elevation/shadow 남용 적발
- [ ] 폰트 패밀리(Pretendard/Wanted Sans)·웨이트·크기가 킷과 대응
- [ ] 아이콘·dot 크기, 이모지/FoodCover 표현이 킷과 일치

### ③ 텍스트·카피
- [ ] 문구가 킷과 일치 — **해요체·구체 숫자**(모호어 금지)
- [ ] 빈/로딩/에러/권한거부 상태 카피가 킷 톤과 일치(차단형 아닌지 등 UX 의도 포함)
- [ ] 라벨·플레이스홀더·버튼 텍스트 일치

## muklog 플레이풀 예외 (오탐 금지)
- muklog 킷은 일반 원티드의 "이모지 금지"와 **다르다**. 음식 이모지·FoodCover·플레이풀 요소는 **킷이 허용한 디자인 기준** → 위반으로 잡지 말 것.
- 킷 `templates/muklog`에 있는 표현은 정답이다. 일반 원티드 규칙과 충돌하면 **킷이 우선**.

## 근사 허용 (RN 한계)
RN이 킷을 100% 재현 못 하는 항목(컬러 그림자·backdrop blur·웹 전용 CSS 등)은 ui-spec.md에 기록된 **"근사+사유"**를 확인하고 **근사 허용**으로 통과 처리한다. 사유 기록이 없으면 ui-publisher에 보강 요청.

## 작업 방식
- **각 화면/컴포넌트 완성 직후 즉시 검증**(incremental). 전체 완성 후 일괄 금지.
- 발견은 **킷 라인 ↔ RN 파일:라인 + 수정 방법**과 함께 보고. 비주얼 이슈는 `ui-publisher`에게 라우팅.

## 출력
`docs/sprint/{slug}/qa-report-visual.md` — 통과 / 불일치(킷 라인↔RN 파일:라인+수정안) / 근사 허용(사유) / 미검증(사유) 4분류. 모든 화면 비주얼 충실도 통과 전에는 "비주얼 완료"로 표시하지 않는다.
